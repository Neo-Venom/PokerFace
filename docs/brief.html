Team Poker Face: RAKSHA, a privacy firewall that reads what a field contains, not what it is called

Track 3 · Secret Wards · Members: [ADD MEMBER NAMES] · Repo: github.com/suyashkrishangarg/PokerFace · offline · CPU-only · no LLMs or pretrained models

1. In one paragraph

RAKSHA de-identifies messy multi-hospital Indian exports (CSV/TSV in four encodings, nested JSON, FHIR R4, notes, WhatsApp forwards) in English, Devanagari Hindi and Hinglish. It links each patient across files and scripts under keyed pseudonyms and defends the release against the voter-roll attacker. Its core idea is two independent signals for every field: the label and the values. A column called holder, abode or रोगी is recognised as a name or address column from its contents. PII found anywhere is then harvested and swept from every other channel (free text, keys, headers, filenames, base64). The system keeps working when headers, ID formats and name pools change.

3. How each part works

  • Ingestion: every file is identified by SHA-256 and the input is opened read-only. Formats are sniffed by bytes as well as extension, so JSON behind .csv is still parsed. PDF, JPEG, XLSX, XML with DTD/entities (defusedxml), truncated JSON, JSON deeper than 500 levels and invalid UTF-8 are quarantined, never copied. Unquoted commas are repaired before profiling. Hostile exports are handled without losing data: stray NUL bytes are blanked, NaN JSON and free-text lines over 64 KiB are quarantined, and so are files named with ;, $( or ...
  • Detection: (a) a clinical shield protects doctors (Dr. plus learned doctor full names), doses (1-0-1, BD x 5 days), labs, ICD/LOINC codes, wards (Ward 7 (Surgery)), eponyms, K/C/O, H/O, C/O <symptom> and ASHA workers. The lexicon is learned at run time from clean documents, drug and diagnosis fields. (b) Shape detectors: any hospital ID shape (prefix + separators + digits), phones in any grouping, Aadhaar (no Verhoeff gate), ABHA, PAN, PINs in address context. (c) Context NER for unlabelled people: Pt X (62M), brought by son X, unke pati X ne, पिता: X, Bed 7: X, honorifics (ji, sahab, didi, garu…), WhatsApp senders. Facility and label words can never become names. (d) Harvest-then-sweep: everything found in pass 1 is swept exactly (normalised, Devanagari digits, homoglyph-folded) from all channels after decoding %XX, HTML entities, \uXXXX, base64 and zero-width tricks. Address fields fail closed: only public district/state names survive.
  • Linkage & pseudonyms: Devanagari is romanised and folded (inherent-a, nukta, vowels, so मोहम्मद ≈ Md. ≈ Mohammad). Multi-key blocking feeds IDF-weighted Fellegi–Sunter scores. Clusters merge in descending score order with hard vetoes (gender, DOB, Aadhaar/ABHA/PAN, conflicting IDs of one hospital system, conflicting names or relatives). Spelling, transliteration or corrupted-age conflicts are waived only when two independent single-person IDs agree, and a record without its own ID that fits two people equally (father and son with one name and phone) stays unlinked. Family phones (different given names) carry little weight, and multi-patient tables (IDs or names in ≥2 headers or keys) are never assigned to one person. Pseudonyms are HKDF-derived HMAC (PSN-XXXXXXXX): stable within a release, unlinkable across secrets.
  • Privacy layer: each patient gets a secret HMAC date shift (30–180 days) applied to every format (ISO, d/m/y, m/d/y, dd-Mon-yyyy, "June 8, 2025", d/m/yy, Devanagari digits, year-less dates), so length of stay and visit gaps stay exact. Age bands always contain the true age (5→10→20 years by cohort size, 85+ top-coded). Village → [ADDRESS], tehsil suppressed when rare, PIN → 3-digit prefix or suppressed, and diagnoses shared by fewer than 4 patients are rolled up.
  • Security: RAKSHA_SECRET is HKDF-split into pseudonym, shift, filename and vault keys, then removed from the environment and never written. The exception hook strips PII from tracebacks, nothing goes to TMP or HOME, and an optional AES-256-GCM vault holds quarantined originals with keys kept apart from data. Files whose names contain PII are renamed with a keyed tag and declared by hash in report.json. Spreadsheet formulas in CSV cells are neutralised (OWASP CSV injection).

4. USP

  • Header-agnostic by design: roles come from values as well as labels, and multi-patient tables are recognised by structure. No practice file names or hospital codes appear in the code, and ID formats are recognised by shape.
  • Cross-script identity with safety rails: the same patient is linked across Latin, Devanagari and Hinglish, while homonyms, spouses sharing a phone and same-hospital re-IDs are kept apart (0 false merges on all six test sets).
  • Measured on data we did not tune on: a 200+ file adversarial generator with a held-out vocabulary (pool B: new names and header labels) and a "hard" level of hostile-export traps, scored with the toolkit's official checkers.

Before the generalisation work the same pipeline scored 55.7 on Gauntlet A (linking F0.5 0.02, 36 direct identifiers surviving); it scored 98.5 on the practice set, which is the memorisation gap the hidden chaos round targets. Today Gauntlet A scores 99.5 and the 60-patient, 6,000-row A21 99.2.

Choices and their cost. Per-patient shifts keep every interval exact; a global shift would be recovered by A5 from two re-identified people. 5-year age bands widen only where a band holds fewer than 5 patients, which costs a little generalisation utility (0.9 → 0.8 per field) and lowers A3/A4. Districts are kept (research value, a public area), villages and house details are removed, tehsil and PIN are coarsened by cohort size, and rare diagnoses are rolled up to the ICD block. Within the practice release, 62.5% of patients are still unique on (age band, sex, district) alone, but the 4-5x larger population register means the attacker confidently re-identifies only the A4 share above.

6. Security design ("assume the server is breached")

  • No raw data is persisted: parsing happens in memory, quarantined originals are either not written or sealed with AES-256-GCM (AAD = file hash) under a vault key derived from the release secret, and the input is never modified.
  • The keys never touch disk or logs: the secret is removed from the environment after HKDF, sub-keys are domain-separated, and different secrets give unlinkable releases (pseudonyms and shifts change).
  • The egress gate re-scans every output file, file name, report.json and records.jsonl (base64 decoded) for harvested identifiers and the secret before exit. stdout and stderr carry only counts.

7. Known limitations

  • Names written only in scripts other than Latin/Devanagari (Tamil, Bengali…) rely on context cues and the harvest from structured fields; there is no script-specific transliteration.
  • English-origin names transliterate imperfectly (मैथ्यू ≠ Mathew). Such records link only through a shared ID, otherwise they stay separate, which is the safe choice for precision.
  • A fragment carrying only a first name and a relative's first name is linked only if that pair is unique. Truly ambiguous fragments stay unlinked by design.
  • Address fields fail closed: a hospital or landmark named inside an address cell is redacted too (small utility loss, no privacy loss).
  • The attack numbers come from our own implementation of ATTACKS.md, and the official attacker may weigh evidence differently. Run time was measured on a 12-core laptop, and the 2-CPU sandbox will be slower but stays far inside the 15-minute limit.
