3How each part works

Ingestion

Files are hashed and sniffed by bytes (JSON behind .csv is parsed); UTF-8/BOM/UTF-16/cp1252 decoded; ragged rows repaired. PDF/JPEG/XLSX, DTD XML, truncated or NaN JSON, JSON deeper than 500, invalid UTF-8, 64 KiB+ lines and unsafe file names are quarantined.

Detection in 3 scripts

A clinical shield (learned at run time) protects doctors, doses 1-0-1, labs, eponyms, wards, K/C/O, C/O <complaint>. Shape detectors catch any hospital ID, phones in any grouping, Aadhaar/ABHA/PAN, PINs. Context NER finds unlabelled people (Pt X (62M), unke pati X ne, मरीज़: X). Finds are swept from every channel after decoding %XX, entities, \uXXXX, base64, homoglyphs and zero-width tricks.

Linkage & pseudonyms

Devanagari is romanised and folded; multi-key blocking feeds IDF-weighted Fellegi–Sunter scores; clusters merge under hard vetoes (sex, DOB, Aadhaar/ABHA/PAN, twins, father/son, two IDs of one hospital). Per-visit IDs never contradict; weak fragments attach only with a clear margin; an ambiguous record stays null. PSNs are HKDF-keyed HMAC.

Privacy layer

Per-patient keyed date shift (30–180 days) keeps every stay and interval exact. A k-anonymity planner over distinct patients picks the most specific truthful age band; rare-condition patients need 2k; l-diversity on conditions; tehsil and PIN coarsen by cohort; house, locality, landmark and village are removed.

4USP: what a plain PII tool does not do

Header-agnostic, never memorised

holder, abode, रोगी or a remarks column of "C/O fever" are classified from label + values; no practice names, hospitals or ID prefixes in the code. Renamed headers, unseen names and new ID prefixes: 0 leaks.

Cross-script identity with safety rails

मोहम्मद ≈ Md. ≈ Mohammad and नायर ≈ Nair link, while homonyms, twins, a father and son sharing name and phone, and spouses sharing a phone stay apart: 0 false merges on every set. Best ideas of our team's 8 prototypes merged.

Generalisation evidence

Third-party stress suite (hostile files, homonyms, voter-list attacker): 98.4 and 98.9 on two seeds, 0/3,063 tokens leaked, 2,370/2,370 medical values, 0 canaries. Merging the best of our 8 prototypes raised the unseen-style average from 99.2 to 99.6. A judge-style run (fresh venv, no network, 2 CPUs) passes check_submission.py: byte-identical repeats, 0 pseudonyms shared under a new secret.

Choices and their cost

Per-patient keyed shifts keep every stay exact, where a global shift would fall to A5. Age bands widen (5 → 10 → 20 years → life stage) only until the class of distinct patients is k-anonymous, so large releases keep narrow bands. Districts stay (public, research value); everything below is removed or coarsened. Residual risk: small releases pay age-band precision; exact stays plus a rare diagnosis remain the strongest attack, so those patients need 2k.

6Security design: assume the server is breached

Nothing raw at rest

Parsing happens in memory, the input stays read-only, quarantined originals are never copied (optional AES-256-GCM vault with the file hash as AAD). TMP and HOME stay empty.

Keys away from data

RAKSHA_SECRET is HKDF-split into pseudonym, date-shift, file-name and vault keys, removed from the environment and never written; a different secret gives an unlinkable release.

PII-free logs

Logs carry counts only; the exception hook strips messages; stdout is one count line.

Egress gate

Every output, file name, report and record is decoded (base64, %XX, entities) and re-scanned before exit; dirty cells are re-scrubbed, persistent leaks quarantined; CSV formulas neutralised.

7Known limitations

  • Names written only in other Indic scripts (Tamil, Bengali) rely on context cues and structured-field harvest; there is no script-specific transliteration.
  • English-origin names transliterate imperfectly (मैथ्यू ≠ Mathew): such records link only through a shared ID.
  • A single note processed alone has no corpus context: a bare village name with no cue can survive, and its age band widens to the safest range.
  • Small releases trade age-band precision for anonymity; k, l and the rare-condition rule are policy knobs in config/policy.yaml.
  • Attack numbers come from our implementation of ATTACKS.md, not the sealed evaluator; run times were measured pinned to 2 CPUs with no network.
